# M0 Vulkan compatibility requirements

Source baseline: current official [xemu-project/xemu `master`](https://github.com/xemu-project/xemu), inspected on 2026-09-30. The probe stores the individual result and evidence in `m0-report.json`.

| Capability | Current Xemu source requirement | Future native Android presenter | Probe |
|---|---|---|---|

| `depthClamp` | Required physical-device feature in [`instance.c`](https://github.com/xemu-project/xemu/blob/master/hw/xbox/nv2a/pgraph/vk/instance.c) | Still required unless renderer/shaders are changed | `vkGetPhysicalDeviceFeatures` |

| `occlusionQueryPrecise` | Required physical-device feature | Still required unless renderer changes | `vkGetPhysicalDeviceFeatures` |
| `shaderClipDistance` | Required physical-device feature | Still required unless renderer changes | `vkGetPhysicalDeviceFeatures` |
| `shaderTessellationAndGeometryPointSize` | Required physical-device feature | Still required unless renderer changes | `vkGetPhysicalDeviceFeatures` |
| `samplerAnisotropy` | Optional in current source | Optional renderer capability | Recorded; absence is not a compatibility failure |
| `wideLines` | Optional in current source | Optional renderer capability | Recorded; absence is not a compatibility failure |

| Formats and limits | `instance.c` currently has FIXME comments for checking formats and VRAM; texture mappings/conversions are in `texture.c`, vertex input formats are in `vertex.c`, and the display target is created in `display.c` | Actual texture, vertex, target, and depth usage must be supported; availability can be format- and workload-dependent | Records raw Vulkan flags and per-role checks: optimal sampled image for mapped texture formats, vertex-buffer support for Xemu vertex formats, optimal color attachment for the RGBA8 display target, and depth/stencil attachment for queried depth candidates. A missing conditional texture format is a compatibility warning requiring workload/fallback analysis, not automatically a startup failure |

The `xemu_current` status in JSON answers whether the current upstream code's explicit requirement is satisfied. External handle exportability is reported separately from extension presence. The `android_path` status distinguishes capabilities that remain needed for NV2A from desktop OpenGL interop that can become `NOT_APPLICABLE` after a native Vulkan presentation path exists. Each format now reports a `roles` array and `usage_checks`; raw feature presence for an unrelated usage does not make the relevant check pass. The texture/vertex role mapping is a source-derived inventory, while whether an unsupported texture format can be converted or avoided in a particular game remains workload-dependent. Refresh this matrix against the pinned source revision before using it as a build gate.
